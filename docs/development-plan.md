# 开发方案与当前边界

Agent Handoff 面向同一台 Mac、同一用户下的本地编码会话。接收端按需通过中转站查找和读取选中的来源会话，源客户端可以已退出。发送方也可以先保存版本并创建指派，接收方稍后从收件箱领取。两条路径复用同一套工作树校验和目标发布逻辑。

## 已实现

| 阶段 | 交付能力 |
|---|---|
| M0 | 用实际客户端区分会话可发现、能打开以及在正确工作树继续执行。 |
| M1–M2 | 提供 Rust CLI 和 stdio MCP，共享 SQLite 状态。支持预览、幂等发布及历史和笔记的有界回读。 |
| M3–M4 | Codex、Claude Desktop Code、DeepSeek Harness 两两转换。从接收端查询候选、选择来源并拉取。查询支持项目过滤、分页及 ID、标题、可见正文子串匹配。 |
| M5 | 冻结来源历史、工具结果和笔记为独立版本。由一个版本给多个接收端创建各自的计划，保留父计划和任务关联。 |
| M6 | 保存带接收方和后续要求的指派。允许离线领取，并发或重复领取同一指派复用同一目标。 |
| 开放接入 | CLI/MCP 运行时注册来源端、接收端或双向 agent。接入方实现本机会话协议即可参与按需拉取、离线领取及后续转交。 |

## 代码与数据的归属

| 部分 | 责任 |
|---|---|
| [接手协调器](../src/app.rs) 与 [指派](../src/assignment.rs) | 管理任务版本、计划和收件箱；校验 Git 工作树、保存 Markdown 笔记并发布目标。 |
| [客户端适配器](../src/agent.rs) | 发现会话、读取历史、创建目标原生记录并给出打开步骤。Codex 和 Claude 复用 txcript 的存储和消息转换。 |
| [DeepSeek 桥接](../adapters/deepseek.mjs) | 使用已安装的官方持久化 SDK 处理会话文件和事件；Rust 侧负责发起本地调用。 |
| [CLI](../src/main.rs) 与 [MCP](../src/mcp.rs) | 同一个可执行文件暴露两个入口，调用共同的应用逻辑。业务错误提供原因、类别、恢复操作和可重试性。 |

代码、暂存改动和未跟踪文件留在原 worktree。版本保存选定来源当时的历史和笔记；计划绑定版本、工作树和唯一目标。实时预览在发布前复核来源与笔记，独立版本按已冻结的内容交付。目标会话创建后，新进度由接收端按原生格式写入，可作为下一跳的来源。

准备和提交阶段的记录用于区分可回收的临时目录和提交结果不明的目录。恢复同库旧备份时，查询不会仅凭当前索引缺少一条计划而删除已经提交的计划文件。

每个内置目标的计划保存一份已交付消息清单；重试和领取时把目标解码为统一消息模型并逐条校验前缀，避免目标被截断或改写后仍报告成功。升级前创建的计划没有清单时，先核对计划记录的 SHA-256，再从保存的原生产物重建基线。缺少基线、摘要不符、读取权限不足分别报告原因，恢复后可用原 ID 重试。外部协议目标继续使用已有的续写前缀校验。

准备、发布和清理共用状态目录旁的稳定进程文件锁，进程退出自动释放。默认等待上限为 5 秒，可通过 `--lock-timeout-seconds` 调整。已有旧式目录内锁时也检查该锁，期限共用。MCP 的 stdio 断开后，排队写入会取消。SDK 准备与已发布目标校验期间不持有 SQLite 写事务，只读查询跳过初始化、迁移与清理。发布提交后先释放文件锁，再等待客户端打开。计划插入和指派绑定在同一短事务提交，并发领取仍复用一个目标。升级后须重启共享状态目录的 MCP 服务，使各进程使用相同的锁协议。

每次 DeepSeek SDK 操作默认限时 30 秒，可用全局参数 `--adapter-timeout-seconds` 调整（正整数，MCP 服务启动时同样适用）。独立监督进程执行限时并检测 Handoff 父进程退出；超时或父进程终止（包括 `SIGKILL`）时终止 SDK 进程组并回收 SDK 子进程。超时返回可重试的 `ADAPTER_TIMEOUT`。未提交的准备目录会被清理，已发布目标保持原样；可用原指派或计划 ID 重试。

## 下一阶段实施顺序

以下计划以 `a20e631` 为基线。该提交已对外部协议目标校验交付历史，并保留来源权限错误的分类。第 1 项已完成三端新旧计划复验，后续从第 2 项开始。每步单独交付，验收结果记入[验收与复现](m0-m6-recheck.md)。

| 顺序 | 改动与交付范围 | 验收判据 |
|---|---|---|
| 1 · 内置目标的历史完整性（已验收） | Codex、Claude Desktop、DeepSeek 在 `apply` 和重复 `claim` 时校验目标 ID、原目录和已交付消息前缀。以目标原生格式实际回读的角色和内容生成摘要。旧计划优先从摘要匹配的原生产物重建基线。基线缺失、损坏或暂时不可读时，返回相应原因和恢复步骤，保留原 ID。 | 分别对三端的新旧计划做可正常解码的中间消息删改，包括工具结果或指派要求，预期返回 `TARGET_INVALID`。合法追加、改标题、调整序列化格式均可重试，恢复目标文件后可用原 ID 继续。移走旧计划基线时须明确报告无法校验。DeepSeek 用官方 SDK 回读一份结构有效、消息被改写的记录。外部协议目标作回归对照。 |
| 2 · MCP 只读契约 | 优先把 `find_sessions`、`get_handoff`、`read_context` 接到只读路径。查询按需打开已有状态，初始化、迁移及清理移到写入或显式维护入口。若分两次交付，先撤掉与实际行为冲突的只读注解，通过无副作用测试后再标注。 | 用真实 stdio MCP 在空状态目录查询内置来源，目录内容保持原样。对已有库读取计划与上下文，核对结果、数据库内容及文件清单。预置可回收的准备目录，查询后仍存在。已初始化但数据库丢失时，返回恢复指引并保留计划目录。 |
| 3 · 笔记绑定管理 | CLI 增加 `memory list --project` 与 `memory unbind --project … --path …`。列表显示储存的路径与可用性，解绑按已保存记录匹配。递归收集笔记时跳过 `.git`、`node_modules`、`target`，对选中的 Markdown 继续执行数量和总大小限制。 | 绑定后删除或改名，在列表找到旧路径并成功解绑，下一次采集可用。另一项目的绑定和已冻结的笔记仍能回读。目录内同时放置正常笔记和超过上限的依赖文档，只有正常笔记进入新版本。 |
| 4 · 一致性备份与恢复 | 提供 `handoff backup PATH` 和 `handoff restore PATH`。先定义备份清单，涵盖 SQLite、计划产物及注册 agent 的协议文件，注明原 worktree 和各厂商原生会话的外部依赖。使用 SQLite 备份接口，协调中转站写操作，对可由客户端独立更新的文件验证复制一致性。恢复先暂存并校验，再切换状态，保留可回退的原状态。 | 在隔离目录备份后，以原计划、版本和指派 ID 恢复并执行。备份期间有写入时取得一致快照或给出可重试结果。截断备份或中断恢复后原状态可用。切换较旧备份并查询，再恢复最新状态，备份之后创建的计划仍能用原 ID 执行。 |
| 5 · 索引、分页与快照复用 | 备份可恢复后再迁移旧库。为父计划、来源版本、任务及收件人的实际查询回填字段并建索引，复用已有的计划状态列。CLI 和 MCP 的版本、收件箱列表增加有界分页，明确排序、游标和旧调用方式。采集在同一事务内判断快照能否复用。 | 用旧库迁移，核对原 ID、父子关系和指派归属。用查询计划及规模样本对比查询耗时；跨页读取无重复、无遗漏。相同来源身份、内容、笔记、worktree/HEAD 和父版本关系可复用，并发采集得到同一版本。分别改变 HEAD、笔记或上游版本，验证产生新快照。 |
| 6 · 保留与清理 | 在备份和引用查询可用后定义归档资格。`gc --older-than 30d` 默认预览，列出对象、大小和原因，显式执行时重新核对引用。待领取指派、可重试计划、仍需追溯的父版本和已交付给客户端的会话都受保护。`waiting_for_open` 与 `open_requested` 表示交付进度，不能证明任务已经结束。 | 先确定哪些任务可由用户归档，再开放实际删除。用旧备份运行预览和清理，只有 `commit-intent` 且在当前库缺行的目录必须保留。恢复最新库，验证较新计划可执行。对明确归档且无受保护引用的样本，核对预览、实际释放量和重复执行结果。 |

错误分类随以上改动迁移。复用现有 `Fault`，在失败发生处确定稳定的 `code`、`retryable` 和恢复操作。验收时比较 CLI 与 MCP 的结构化结果，并检查修改提示措辞后错误分类保持一致。

## 第 2–6 步实现约定

本轮实现在 `feat/handoff-state-lifecycle` 分支。只读 CLI/MCP 查询使用只读连接，空目录查找来源时使用内存状态。初始化、迁移和遗留准备目录清理在写入入口执行。笔记新增 `list`、`unbind`，解绑支持已删除的路径，递归绑定跳过 `.git`、`node_modules` 和 `target`。

`backup PATH` 使用 SQLite 备份接口和 SHA-256 文件清单，保存计划产物与协议 agent 目录。复制前后验证文件一致性。`restore PATH` 先暂存校验备份，再创建当前状态的回退备份。恢复限定在备份记录的原状态目录，以维护计划的绝对路径身份。恢复旧库时保留后来创建的计划文件及协议客户端续写。原 worktree、内置客户端会话目录是需要单独保留的外部依赖。

查询使用生成列和索引，在写入入口事务迁移旧库。`versions`、`inbox` 默认每页 100 条，上限 1000 条。下一页传入返回的 `next_cursor` 作为 `--cursor`，MCP 参数为 `cursor`。游标基于 rowid，新增记录不会重复前一页内容。仍接受 `offset`。来源身份、字节摘要、笔记、工作树和 HEAD、父计划一致时复用最近版本，并发采集在事务中判断。

`archive TASK_ID` 显式归档任务，待领取指派阻止归档。重新采集、准备、发布或指派会取消归档资格。`gc --older-than 30d` 默认仅预览，`--execute` 执行，以归档时间计算期限。活动计划、指派及其父计划和父版本受保护。未知提交目录和客户端原生会话保留。清理先隔离计划目录，使用含状态库身份的日志及数据库提交记录；中断后下一次写入恢复目录或完成回收。返回的字节数为计划文件大小，SQLite 空闲页由后续写入复用。

## 恢复一致性修正

恢复先构建完整的暂存状态，核对所有计划文件冲突后再切换目录。对协议会话，备份是本地历史的合法续写时采用备份，本地较新时保留本地，空白或损坏的本地记录用有效备份修复。两侧有效但已分叉时返回 `RESTORE_CONFLICT`。所有注册 agent 的空会话目录由备份数据库重新创建。较新且未被旧数据库索引的计划目录继续保留。

切换使用状态目录旁的稳定锁和持久化日志，旧状态作为 `rollback_state` 保留。当前数据库健康时还生成可供命令恢复的 `rollback_backup`。当前库损坏或为空时保留原始目录后恢复有效备份。切换期间中断，下一次写入先处理日志，再开始业务操作。故障发生在原目录移走后、暂存目录启用前时，会恢复原目录。只读查询不会执行恢复日志修复。

只读查询复制数据库及 WAL、回滚日志到私有临时目录，检查复制前后的源文件一致性，再由 SQLite 构建内存查询快照。源目录不创建 `-wal`、`-shm`，有已提交 WAL 时也能读取最新记录。回滚日志恢复只发生在私有副本中，未提交记录对查询不可见。该实现有完整数据库复制成本，大状态库的端到端查询性能需另行量测。

## 工程与分发待办

- **安装与诊断**。优先提供带校验和的 macOS 预编译包和 `handoff doctor`。用未安装 Rust 的环境验证安装、版本查询及 MCP 启动。诊断覆盖所选客户端的目录、权限、SDK 和状态库，默认输出隐藏会话正文及凭据。
- **构建与兼容性**。分步引入 Clippy、依赖审计和 Cargo 缓存。Linux 先验证构建，再确定支持范围。锁定依赖 `txcript 0.14.4` 声明最低 Rust 1.96；调整最低版本需同时验证锁定依赖和项目构建。
- **适配器和测试**。分别验证来源模型作为历史署名和作为目标运行配置的行为，再决定清理字段。用确定性同步替换提交中断测试中的长 SQLite 计算。适配器诊断若需落盘，采用显式开启的脱敏私有日志。
- **使用入口**。任务和计划浏览在分页查询可用后补齐。注销 agent 前先定义待领取指派和既有会话的去向。Shell 补全与 Homebrew 分发可独立排期。

## 后续扩展

协议客户端按[本机 Agent 接入协议 v1](agent-protocol.md)自助注册。私有格式的导入、窗口打开与工作目录恢复由客户端实现；中转站统一承担版本、指派和交付。

尚待扩展的范围包括向当前窗口注入上下文、接收端上线提醒、自动接手回执，以及更多会话格式与媒体类型。当前产品的操作说明和验证步骤见[中文 README](../README.zh-CN.md) 和[验收与复现](m0-m6-recheck.md)。
